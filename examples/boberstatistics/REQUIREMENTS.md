# Requirements

Every change is driven by a requirement, and its commit names the requirement
(GIT1). A requirement may be a single sentence — the bar is that it exists and
was written before the change, not that it is formal.

Give each one a stable id (`R1`, `R2`, …) so commits can reference it. Do not
reuse an id after retiring it.

## Format

```
## R<n> — <short title>
<What must be true when this is done. One sentence is enough.>
Status: open | done | dropped
```
